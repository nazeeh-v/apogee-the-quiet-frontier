# APOGEE — challenge pitch

## Short description

APOGEE turns mission design into a first-person space survival adventure. A stranded explorer salvages wrecks, repairs a habitat, designs equipment, recovers scientific signals and builds a return craft. A separate engineering laboratory lets players model Earth, lunar and Martian science missions with documented equations.

## Problem and solution

Subsystem trade-offs are abstract when students only see separate equations. APOGEE gives them consequences. Oxygen storage extends a trip but adds mass. A spectral scanner enables science but consumes design power. A stronger drive competes with the equipment needed for a return stage. Science is valuable only when it reaches the habitat and is transmitted home.

## Challenge alignment

| Requirement | Adventure | Mission Design Lab |
| --- | --- | --- |
| Objectives | Restore habitat, recover three surveys, return home | Three destination-specific scientific missions |
| Spacecraft | Craft and reclaim nine module types | Select bus, engine, solar, antenna and payload |
| Resource management | Oxygen, energy, cargo, finite materials and credits | Budget, mass, power, battery, fuel and data |
| Engineering trade-offs | 300 kg mass limit and generation/load constraints | Rocket equation, orbit period and solar distance |
| Launch | Integrate and launch a return stage | Destination-specific launcher capacity and insertion |
| Communications | Surveys must be returned before relay/departure | FIFO science queue and downlink operations |
| Simulation | Real-time free flight, radiation, survival and discovery | Seeded operations and a 32-run rehearsal |
| Evaluation | Progress, field log, surviving equipment and departure | Engineering review, debrief, scores and flight comparison |

## 90-second demonstration

1. Show the ringed world from the cockpit and the damaged habitat.
2. Select the wreck on the map, engage cruise assistance, and salvage materials.
3. Dock and explain the fabricator's mass, power and mission budget.
4. Install life support, then show the scanner and shielding requirements.
5. Scan a signal and explain why buffered data must be returned safely.
6. Show an advanced save where the return stage exceeds mass capacity until an optional module is reclaimed.
7. Launch the completed return mission.
8. Open the Mission Design Lab to show its documented engineering checks and NASA references.

## Scope and disclosure

The adventure is an original fictional world, with authored survival and flight mechanics. It does not solve realistic life-support systems or orbital propagation. The separate lab uses physical equations with explicit game assumptions. Both are dependency-free browser experiences with local saves and no account requirement. Browser visual QA and actual GPU shader behavior have not been verified in the current build environment.
